## 一、AI 源图（提示词要点）

工具：Cursor 内置 `GenerateImage`，共 7 张 16:9 源图（`src/`）：手臂 ×8、下肢 ×6、胸腔 ×6 + 头 ×6、道具 ×5、俯视地块 4×2、补拍俯视地块 1×4、整身敌人对照组 ×5。

提示词的共同写法：
- **一张图 = 一个槽位的一整排变体**（同一次生成里风格最统一），“one horizontal row with wide empty gaps”，方便按连通域切分。
- **纯品红 `#FF00FF` 背景**（地块表用黑色分隔沟），霓虹色避开品红。
- 写明部件朝向和长宽比：手臂“竖直、肩在上”，下肢“wider than tall”，胸腔“headless, reactor core in the exact center”。
- 材质约束：“neutral dark gunmetal grey + only one or two tiny glowing neon accent pixels”，不要文字、阴影和背景细节。

## 二、锁定调色板（32 色）

| 组 | 色键 | 用途 |
| :--- | :--- | :--- |
| 环境 | `E0`~`E5`（`#07080d`~`#2e2a45`），`E6 #3a4258` | 地面/墙体明度 ≤27%；`E6` 只用于 L 角标与墙顶 |
| 躯体灰阶 | `B1`~`B5`（`#3b4152`~`#e8edf5`） | 中性金属，按部件亮度分位映射 |

| 材质 | 工业黄 `YE/YED`、水 `WA/WAL`、冰 `IC/ICL`、火 `FI`、焦痕 `SC`、结构 `ST`、玻璃 `GL` | 破拳套、四力地表、窗框 |

每个脚本最后都会做 `palette_audit` 断言：原生精灵/地块出现任何调色板外的颜色就直接报错。

## 三、后处理步骤（`pixelkit.py` / `extract_parts.py`）

1. **抠图**：`min(R,B) − G > 60` 判为品红背景 → 1 次开运算去 JPEG 噪点。
2. **切分**：膨胀 7px 后做连通域标记（把火花、碎线并回主体），面积 <1500px 的丢弃，按行（y 聚类）再按 x 排序，并断言数量与提示词一致。
3. **缩放到槽位原生尺寸**：手臂 7×11、下肢 12×6、胸腔 10×8、头 6×5、货舱 12×12、地块 24×24。按比例缩放，允许横向最多拉伸 3 倍（AI 画的手臂约 1:4、腿偏高）。用 BOX 面积平均分别计算覆盖率和颜色。
4. **霓虹保留**：块内霓虹像素（饱和度 >0.5 且明度 >0.55）占比超过阈值（头部 3%，其他 10%）时，只取霓虹像素的平均色，保证 1~2px 焦点不会被平均成灰色。
5. **Alpha 二值化**：覆盖率 >45% 记为不透明，其余全透明（只有 0/255 两档）。
6. **锁色**：灰色像素按**本部件**亮度分位（25/60/88/98%）映射到 `B1`~`B5`，这样不同批次源图的明暗会被统一；彩色像素按加权 RGB 吸附到彩色子集；货舱、散热器等整件着色道具只吸附到各自的子集。
7. **墨线**：外轮廓上的非霓虹像素压成 `E0`，作为 Caves 式 1px 呼吸黑边。
8. **地块**：网格/分隔沟检测 → 方形裁切 → BOX 缩到 24×24 → 按地块类型限定调色板子集（地面只允许 `E0`~`E5`）→ 代码补 2×2 L 角标；墙体加 1px 顶边亮边 + 2px 底部投影；冰面先乘 0.72 增益压进明度预算，再补 2 道斜向高光。
9. **拼装**（`rig.py`）：固定锚点，背部 4 个 2×3 指示块位于 y=0（橙=货舱、冰蓝=散热、暗灰=空位，代码绘制）；头 6×5 底边贴 y=8；胸腔 10×8 在 (5,8)；下肢 12×6 底部居中；左右臂 7×11 顶边 y=7、各压胸腔 1px，右臂水平镜像。断臂时肩部换成 2px 火花断口，被斩落的手臂把**同一张贴图**旋转 90° 作为地面道具。
10. **展示放大**：只用最近邻 8×（场景 6×）。
11. **场景光照**（`make_mockup.py`）：像素层 6× 放大后，在 1920×1080 原生分辨率上叠加高斯点光源（窗外城市青光、火焰、冰面冷光、各单位反应堆颜色、电弧沿线）→ 光照色调映射 `ambient 0.58 + 1.1·(1−e^(−L))` → 霓虹像素保持自发光 → 三档半径 Bloom（8/26/70px）→ 暗角 + 6% 扫描线 → 最顶层叠加不受光照的明牌 UI（意图箭头、滑行编号、破窗/坠落警示、锁定角标、落点幽灵剪影）。

## 四、坦率评估

**做得好的地方**
- **同一次生成内风格高度一致**：8 条手臂、6 个胸腔都是同一种枪灰装甲语言，切分数量第一次就全部对上，品红背景抠图干净。
- **5 槽拼装在 20×22 内确实可读**：手臂靠墨线和压胸腔的层次与躯干分开；橙装刃、黄色破拳、青色刃隔着半屏也能认出来；背部“4 橙 vs 2 橙 2 蓝”一眼可辨。换件（双足 → 履带、电击棍 → 高频刃）只是换一个参数，零重画。
- **断臂复用贴图**完全成立，场景里的“断臂导电桥”和身上的手臂是同一张图。
- **跨分辨率反差**很有效：硬边马赛克 + 平滑光晕的组合，很接近 Caves 的质感。

**AI 吃力的地方（需要代码兜底或人工修整）**
- **生成的不是真像素画**：输出是约 8~10 倍、不对齐网格的“伪像素”，真正落到 7×11 时细节大量丢失。手臂源图比例约 1:4，必须横向拉伸 3 倍才能填满槽位；双足腿和逆足腿在 6px 高度下 1× 几乎分不出来。**下肢是 5 槽里可读性最差的一槽**。
- **小尺寸焦点像素容易丢**：6×5 头部的红色眼点第一次处理时整个消失，靠降低霓虹阈值才找回；骇客义眼只剩 1px 绿点。
- **不同次生成之间会漂移**：胸腔表的伪像素块比手臂表更粗、整体更暗。靠“按部件做亮度分位”的灰阶归一化才拉齐，但线条粗细的差异仍然看得出来。
- **透视不听话**：第一张地块表把落地窗画成了等距视角，只能补生成；道具表是 3/4 俯视，和纯俯视地块放在一起略有违和（货舱尤其明显）。
- **明度预算 AI 不懂**：冰面原图明度约 81%，会和角色抢视觉主权，需要乘增益压暗；墙和地面在俯视下几乎一样，只能靠代码加倒角；冰面高光斜纹在量化时丢失，靠代码补回。
- **背部 4 指示块和反应堆颜色不能交给 AI**：对照组里 AI 虽然画了 4 个小方块，但缩到 20×22 后被压成 1px 线，颜色也不对应任何规则。现在这两项都由代码按游戏状态绘制，这也是 Caves+ 方案本身的建议。
- **对照组结论**：整身直缩的轮廓更像人，但槽位边界糊在一起、不能换件。这证明**分槽生成 + 固定锚点拼装**是必要的。
- **光照容易过曝**：第一版场景里电弧、火焰和反应堆光叠加后，单位直接变成白块，加色调映射后才恢复可读。光照层必须设上限，否则会直接吃掉槽位可读性。

**量产建议**：把通用生图模型换成原生网格模型（Retro Diffusion / PixelLab，开启 `target_palette`），直接按槽位尺寸出图；保留本流水线的切分 → 锁色 → 二值 Alpha → 锚点拼装 → 调色板审计作为 CI 检查；下肢每件预留约 10 分钟人工修像素；背部指示、反应堆热量色、元素状态、电弧等全部继续由代码 / PixelFX 驱动。

> **该建议已落地**：Retro Diffusion 的接入方案、43 条可直接粘贴的槽位提示词、以及可运行的 `rd_gen.py` 见 `docs/retro-diffusion-prompt-kit.md`。核心修正是"生成的像素尺寸"——不再要求模型直接画 6×6（任何模型都画不出来），而是按槽位 4× 超采样生成、再本地 ÷4 块取众数落位，保证像素网格严格对齐且无需改 `rig.py` 锚点。

## 五、v2 咬合骨架升级（修复腿部偏小与部件悬空缝隙）

针对 v1 审阅反馈“腿部偏小、部件衔接生硬、缝隙过大”，在保持 `20×22` 角色画布、`24×24` 地块与 32 色调色板不变的前提下，完成了四重根因修复与五项管线升级，并重生成全部三张样张（`enemies-sheet.png` 已附 v1 与 v2 同屏对比卡）：

1. **50% 下肢机身比 + 补拍宽跨步 SD 机甲下肢源图（`src/src-legs-v2.jpg`）**：胸腔收紧至 `10×6`、手臂收至齐胯 `5~6×8~9`，下肢扩容至 `14~16×10~12`（高裆位分叉，完整露出大腿、膝甲、护胫与战靴；四足与履带同步加宽）。
2. **取消单件内蚀黑边，改为合成后统一外轮廓**：单部件保留 100% 金属体积（`outline=False`），全部槽位合成后仅向外部背景外扩 `1px E0` 墨线，彻底消除吃掉细腿与叠出 2px 双黑沟的问题；断臂落地当道具时再单独补外描边。
3. **灰阶职责分离**：实体装甲受光面强制锁在 `B2~B5`（明度为暗地板的 2.5~4.5 倍），将最暗灰 `B1` 专用于合成阶段的 `1px` 分件凹槽与膝关节折线，消除背光侧融入暗地板造成的假裂缝。
4. **四处显式机械关节咬合**：肩轴球铰压入胸肩 1px 并填平腋下空隙 + `1px B4` 肩铆钉；腰际绘制液压腰扣并保持中央脊椎高亮金属不断裂；头部下沉 1px 嵌进胸领；4 颗背部模块直接长在双肩 `B2` 背架横梁上，取消头顶悬空。
5. **小部件霓虹焦点上限保护（`max_neon_px` + `strict_neon`）**：头部与膝灯最多保留 2 颗最高饱和度霓虹像素，防止压缩色偏污染灰阶装甲。

## 六、v3/v4 灵动分级体态与 24 色双阶平涂升级（消除笨重与碎像素）

针对后续两轮审阅反馈（①“v2 整体偏大笨重、缺乏灵动感”；②“v3 颜色仍偏杂、画面偏碎”），完成小像素角色姿态与色板归并改造，重生成全部三张样张：

1. **分级像素体量 + 3/4 微侧身错步姿态（解决笨重感）**：不再让所有单位塞满 `20×22`，改为轻中型单位缩至 `11×13~15×17`（地格留白约 50%），仅重装执法者与 Boss 保持 `19×20` 压迫感；站姿改为 3/4 微侧身、前后腿 `1px` 高低错步（远腿暗一阶、近腿亮一阶）、收腰倒梯形与 `35°~45°` 斜向持械，肘下留出负空间呼吸孔。
2. **24 色色相偏移主色板**：从 32 色精简至 24 色，剔除过渡杂色，暗部统一向 `224°~228°` 冷靛蓝偏移；机甲金属锁死为 `B2 (#465575 冷钴暗块)` 与 `B3 (#96a8c4 冰银亮块)` 双阶对比。
3. **双阶平涂归并 + 四邻域去噪（单角色总色数严控 4~6 色）**：弃用 5 阶灰分桶渐变，改为全身金属仅用 `B2/B3` 两阶大色块（Pixel Clustering）并执行整身四邻域去噪，孤立单像素金属噪点从 26% 降至 `0%`；单部件锁死唯一焦点色，背部 `2×2` 模块改为贴背纯色块（货舱纯橙、散热纯青、空槽不画横梁）。实测含外轮廓总色数：无人机 4 色、常规敌兵与玩家 5 色、Boss 6 色。
4. **地格同步去噪平涂**：暗地面压至 `E1/E2`（明度 19%），清除缩图产生的雪花噪点。
