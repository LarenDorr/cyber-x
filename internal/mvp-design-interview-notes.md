# 《Cyber-X》MVP 机制缺口分析与制作人访谈路线图

> **文档用途**：作为编写 `/cursor/stores/bc-cb76bd7a-4096-4324-9a66-e2a728347fac/docs/mvp-game-design.md` 前的内部设计推演底稿，全面梳理从高层创意（`project-context.md`）与视觉管线规格（`game-art-design-research.md`、`internal/art-samples-pipeline/`）落到可编码 MVP 之间的核心机制缺口、跨支柱设计张力及两轮制作人对齐问题单。

---

## 一、六大核心设计缺口与跨支柱张力拆解

### 1. 单局 Raid 与「搜打撤」循环结构（当前状态：待定）
- **核心张力**：
  - 《陷阵之志》采用孤立小房间（4~5 回合自动胜利），解谜密度极高，但缺乏《Quasimorph》式的“见好就收还是冒死再贪一件”的撤离拉扯；
  - 《Cogmind》采用大型迷宫探索，但大量空走廊跑图会稀释单回合明牌棋盘博弈密度，并引入复杂的视野迷雾（FOV）与跨房间仇恨状态切换。
- **关键待决点**：
  1. 单局是由 **3~4 层电梯串联的紧凑单屏房间** 组成，还是 **单房波次**，或是 **同层多房间破门连通图**？
  2. 什么动态压力源阻止玩家在房间里无限刷回合慢慢捡垃圾？（如企业安保增援倒计时 / 楼层电力过载封锁 / 电梯开门等待回合）。
  3. MVP 是否需要一个极简的**单屏局外黑市机库**（仓库存取 + 配装入场），以闭环“撤离带出橙装 -> 下一局装上爽玩”的正反馈？

### 2. 棋盘尺度、回合结构与行动经济（双臂 + 反应堆耦合）
- **视觉与分辨率硬约束**：
  - 美术规范已锁定 `24×24 px` 地块与 `20×22 px` 单朝向角色（见 `/cursor/stores/bc-cb76bd7a-4096-4324-9a66-e2a728347fac/internal/art-samples-pipeline/rig.py`）。
  - 在 `1920×1080` 横屏下，若采用 `4×~5×` 整数倍像素放大（单格 `96~120 px`），留出左右两侧 ANSI 战术检视面板（5 槽结构图、敌方意图详情、热量条与回溯历史）后，黄金棋盘尺寸恰好落在 **`8×8` 至 `10×9`** 区间。在这个尺度下，“冰滑 ×3 格”刚好横跨 1/3 张地图，视觉冲击力最强。
- **双臂槽位与行动次数张力**：
  - 角色同时装备 **左臂** 与 **右臂** 两件独立武器/工具。若严格照搬《陷阵之志》每回合永远只能“1 移动 + 1 攻击”，双臂在同一回合内无法打出左拳造环境、右刀收割的连携，胸腔反应堆“决定可超频程度”也缺乏直接载体。
  - 若引入「基础 1 移 1 动 + 消耗热量超频（Overclock）额外激活副手/热插拔」，即可将胸腔反应堆与背部散热槽深度咬合进核心行动循环。

### 3. 明牌意图 + 回合内免费回溯（Undo）与概率掉落的根本悖论
- **核心悖论**：
  - `project-context.md` 同时提出：**回合内免费撤回**（类《Tactical Breach Wizards》）与 **伤害类型决定战利品完好度百分比**（爆炸 10% / 斩击 90% / EMP 85% 带病毒），而在高光瞬间 ② 又描述“高频刃 100% 无损斩下义体”。
  - 若战斗中存在真随机掉率且允许免费 Undo：
    - 重掷种子 = 玩家无限撤回刷 10% 爆炸掉装；
    - 固定格子种子 = 玩家砍一刀看碎了 -> 撤回 -> 换旁边一格再砍试种子，把战棋异化为繁琐探雷，且 90% 斩击一旦轮到 10% 碎裂会产生强烈受骗感。
- **三大破局方向**：
  - **纯确定性硬规则**（战斗内 0 随机，完好度由「伤害类型 × 目标受控状态」100% 决定并在悬停预览中明牌显示）；
  - **延迟揭晓盲盒制**（战斗中斩落统一为带预期完好率标签的未鉴定模块，回合结束锁死或撤离回机库才开奖）；
  - **混合双轨制**（常态走绑定单位对的固定种子，但触发眩晕/冰封等解谜条件时保底 100% 无损拆解）。
- **隐藏延伸张力（无平民建筑下的《陷阵之志》走位白嫖问题）**：
  - 《陷阵之志》因为敌人锁死攻击“地面建筑”，玩家不能一走了之；《Cyber-X》单主角若所有敌人只锁定主角脚下那 1 格，主角每回合走开 1 格就能无伤躲掉全场攻击，无需推拉解谜。
  - **系统解法（第 2 轮细化确认）**：① 敌人火力采用直线贯穿/扇形压制/近身追击锁定混编；② **地上的掉落橙装、满载货舱与冷却设施本身就是“易碎保护物”**——敌方炮火扫过会将地上的稀有义体炸成废铁，迫使玩家为了护宝主动推开或骇偏敌人！

### 4. 涌现引擎 MVP v0.1 最小正交规则集与 Z 轴取舍
- **空间维度张力**：
  - 文稿提及“80 楼破窗坠落”与“跳跃腿无视高低差”。在 `24×24` 正交俯视微像素棋盘上，若引入完整的室内多层高台（0 层/1 层/2 层 + 斜坡 + 高台边缘遮挡），渲染层级与跨层视线（LoS）复杂度陡增且易产生像素透视歧义；
  - 若采用 **「单层平面棋盘 + 外圈玻璃深渊（80F Abyss）/ 室内天井坑 + 半高障碍物（货舱/设施）」**，则能保持 100% 棋盘可读性，并将逆足跳跃腿定义为“可跨越单位/货舱/危险地表跳跃位移”。
- **五大高光瞬间的零特判系统闭环验证表**：

| 高光瞬间 | 涉及作用力 | 涉及实体/地表标签（Tags） | 纯系统流转链路（零脚本特判） |
| :--- | :--- | :--- | :--- |
| **① 15伤破拳秒300血Boss** | `Cryo` + `Kinetic` | 冷却管 `[Fragile, CryoSource]`、冰面 `[ZeroFriction]`、玻璃窗 `[Fragile]`、窗外 `[Abyss]` | 打破冷却管 -> 铺设冰面 -> 动能推击进入冰面触发滑行倍率（×3 或滑至阻挡）-> 撞碎脆弱玻璃 -> 落入深渊即死（销毁全身部件） |
| **② 弃货舱垫窗保橙装+热插拔** | `Kinetic` + 斩击拆解 | 货舱 `[HeavyBlocker, Conductive]`、状态 `[Stunned]`、外挂部件 `[Severable]` | 投出背部货舱占住窗前格 -> Boss 冰滑撞上 `[HeavyBlocker]` 停下并陷入碰撞 `[Stunned]` -> 高频刃精准斩落右臂橙武 -> 原 `7×11` 贴图旋转 90° 落地 -> 玩家焊入自身断臂槽 |
| **③ 废铁机械臂搭积水导电桥** | `Electro` | 积水 `[Conductive]`、断臂道具 `[Conductive, Pickupable]` | 将断臂/废件扔在两滩不相连积水之间的干地格 -> 补齐四邻域 `[Conductive]` 连通图 -> 对一端放电即全网传导 |
| **④ 黑入视觉义眼偏转 90°** | 电子骇入 + `Electro` | 敌方 `[OpticSensor]`、意图向量 `IntentDir`、积水 `[Conductive]` | 黑客攻击改写目标 `IntentDir` 顺/逆时针偏转 90° -> 实时重算明牌预览线指向积水 -> 敌回合自轰水面电翻水里同伙 |
| **⑤ 拆散热器 4 货舱红温漏电** | `Thermal` + `Electro` | 反应堆 `[Overheated]`、周边 `[Conductive]` | 0 散热器满载货舱 -> 热量跨过红温阈值进入 `[Overheated]` -> 自身微损但每回合/超频时自动向脚底及相邻 `[Conductive]` 格放电 -> 化身自走电弧源 |

### 5. 5 槽身体受击损毁、热插拔与背部热量经济
- **部位血条 vs 明牌算计**：
  - 纯正《Cogmind》每次受击按覆盖率随机掷骰打中核心或某件装备，若直接照搬会破坏明牌确定性与免费 Undo。
  - 需要确定：采用 **「核心总 HP + 外挂部件耐久护甲 + 条件精准拆解/重创替死断肢」** 的零随机模型，还是 **按攻击朝向（左/右/正）分摊伤害到对应槽位**，或是 **纯核心 HP 仅击杀结算掉落**。
- **美术管线 `Head (6×5)` 槽位对齐**：
  - `rig.py` 中实际拼装含 `head`、`chest`、`legs`、`arm_l`、`arm_r`、`back(×4)` 六个视觉分区。需确认 `head` 在玩法上是否保持为 **非热插拔的底盘视觉/义眼词条层**（承载 `[OpticSensor]` 供骇入偏转，不增加玩家背包管理负担），维持 5 大装备槽的精炼度。
- **背部 4 槽（货舱 vs 散热器）数值闭环**：
  - 货舱必须与“局外带出上限”强绑定（如：身上焊着的装备自动带走，**额外战利品每带走 1 件必须占用 1 个背部货舱槽**），才能让贪婪真正挤占散热空间。

### 6. MVP 目标技术栈、视觉精度起点与内容边界
- **技术与资产协同**：
  - 共享 Store 内已跑通 Python 像素拆件脚本与首批 Caves+ 微像素样片（8 种手臂、6 种下肢、6 种胸腔、5 种道具、12 种地块，见 `/cursor/stores/bc-cb76bd7a-4096-4324-9a66-e2a728347fac/internal/art-samples-pipeline/build/manifest.json`），且 `patch-gg/pixelfx` 原生为 JavaScript/Web 双缓冲模块。
  - 需与制作人拍板：MVP GDD 是面向 **Web TypeScript（PixiJS/Canvas + `pixelfx`）直接接入 Caves+ 微像素积木** 的可玩垂直切片，还是先做纯符号灰盒，或是面向 Godot / Unity 独立客户端。

## 二、多轮制作人对齐访谈路线图（Interview Roadmap）

为保证访谈既透彻又不造成决策疲劳，拆分为 **两轮递进式对齐**，全部对齐完毕后再执笔撰写 `/cursor/stores/bc-cb76bd7a-4096-4324-9a66-e2a728347fac/docs/mvp-game-design.md`。

### 第 1 轮（当前执行）：锁定 6 大核心骨架决策
聚焦决定系统底层数据结构的 6 个架构级问题（每题均提供 A/B/C 具体方案、利弊权衡与推荐项）：
1. **Q1 单局 Raid 推进与撤离博弈结构**（电梯逐层连战 vs 单房波次信标 vs 同层连通多房破门；以及极简机库闭环）
2. **Q2 棋盘尺寸与回合行动/双臂超频经济**（`9×9` 1移+1动+产热超频双持 vs `8×8` 严格1移1动 vs `10×10+` AP 行动点制）
3. **Q3 明牌免费回溯（Undo）与战利品完好度的兼容机制**（100% 确定性硬规则预览 vs 固定种子+延迟盲盒鉴定 vs 常态固定种子+眩晕保底 100%）
4. **Q4 涌现引擎 MVP 空间与规则边界**（平面棋盘+外圈玻璃深渊+全 5 大高光系统闭环 vs 引入室内多层高低台 Z 轴 vs 极简裁剪子集）
5. **Q5 5 槽受击拆解模型与背部「货舱/散热器 × 红温漏电」循环**（核心HP+精准拆解+三段温区红温放电 vs 朝向部位分摊血条+过热毁件 vs 仅核心HP末刀掉装+超频冷却条）
6. **Q6 MVP 目标技术栈、视觉落地起点与首发体量**（Web TS + Caves+ 微像素积木 + `pixelfx` 垂直切片 vs Web 纯符号无局外灰盒 vs Godot/Unity 客户端架构）

### 第 2 轮（待第 1 轮回复后追问）：收敛细节规则、边界特例与精确配额
根据第 1 轮选定的骨架，针对性确认 4~5 个实施级细节（不再发散大方向）：
1. **敌方明牌意图与「无建筑护楼」锚点细则**：敌兵被推离/断臂后的意图重算规则，以及敌方火力是否会摧毁地上未捡起的橙装/货舱（以此逼迫玩家护宝解谜）。
2. **电子战（义眼偏转 90° & EMP 病毒件）与热插拔细则**：视觉骇入的触发方式（专属黑客臂 `data_spike` vs 通用耗热指令）、战场当场焊装的消耗、以及焊上“带病毒义体”后的具体故障词条表现。
3. **四力地表状态冲突表与传导边界**：同格冰/水/火/电覆盖矩阵、滑行碰撞伤害公式、导电最大跳数。
4. **数值标尺与 `Head` 槽位定位**：采用《陷阵之志》小整数标尺（如 `2~15` HP）还是保留文稿示例的中整数标尺（如 `15` 拳伤 vs `300` Boss HP）；确认 `rig.py` 中的 `Head` 仅作底盘视觉与 `[OpticSensor]` 词条载体。
5. **局外黑市机库规则与 MVP 首发资产清单**：战败惩罚底线（保底工兵素体）、蓝图/废铁回收循环，以及首批落地的义体、敌人、机关精确数量表。
